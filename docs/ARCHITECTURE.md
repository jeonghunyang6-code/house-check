# house-check 아키텍처 설계

> 목표: 송희구 작가의 시세 해석 관점(거래량·신고가·유동성·공급을 함께 읽기)을
> 데이터로 자동화한 **수도권 아파트 시장 분석기**.
>
> 참고 화면: APTIE(오늘의 실거래 / 거래량 / 가격동향 / 시장지표 / 입지분석) 10장.

---

## 0. 설계 원칙

1. **미확정 숫자를 확정치처럼 비교하지 않는다.**
   실거래 신고 기한(계약 후 30일) 때문에 한 달 거래량은 최대 61일에 걸쳐 쌓인다.
   모든 거래량 비교는 "같은 신고 경과일" 기준으로 한다.
2. **등록일은 우리가 직접 만든다.**
   국토부 API에는 계약일만 있고 신고(등록)일이 없다. 매일 스냅샷을 떠서
   처음 나타난 날을 `first_seen_date`로 기록한다. 과거로 소급할 수 없으므로
   **수집기를 가장 먼저 가동**한다.
3. **지표와 해석을 분리한다.**
   수치 계산(분석 계층)과 "그래서 어떤 국면인가"라는 해석(인사이트 계층)을 나눠,
   해석 규칙을 코드 수정 없이 바꿀 수 있게 한다.
4. **지역 범위는 수도권(서울 25개 구 + 경기 + 인천)**, 서울부터 순차 확장.
5. **개인용 도구.** 로그인·다중 사용자·트래픽 대응은 만들지 않는다.
6. **API는 필요해지는 시점에 하나씩 연결한다.** 키가 없는 소스는 해당 기능을 끄고
   나머지는 동작하게 한다(소스별 어댑터 + `.env` 키 유무로 활성화).

## 4. 핵심 로직

### 4.1 일일 스냅샷과 등록일 (`first_seen_date`)

```
매일 06:00 KST
for 지역코드 in 수도권:
    for 계약월 in [당월, 전월]:          # 신고 기한상 이 두 달만 변동
        rows = API(지역코드, 계약월)     # 전체 페이지
        upsert deals by deal_key
          - 처음 본 키   → first_seen_date = 오늘, event = 'registered'
          - 해제로 바뀜  → cancelled_at = 오늘,     event = 'cancelled'
          - 값이 바뀜    → event = 'modified'
```

- `deal_key` = 단지일련번호 + 계약일 + 전용면적 + 층 + 거래금액 (API에 거래 고유 ID가 없음)
- 공휴일 다음 날은 신규 등록이 없다. 일별 등록건수는 **영업일 기준**으로 비교한다.
- 수집 첫날에는 이미 있는 거래가 전부 "신규"로 잡힌다. 그래서 첫 실행은 `bootstrap`
  모드로 돌려 `first_seen_date`를 NULL(미상)로 둔다.

### 4.2 거래량 시차 보정

- **신고 경과일** = `first_seen_date - 계약월 1일 + 1` (1–61일, 차트는 60일로 고정)
- **전월 동시점 대비** = 당월 경과일 *d*일차 누적 ÷ 전월 *d*일차 누적 − 1
- **집계율(%)** = 오늘 경과일 ÷ 61. 화면의 "집계중 17%"가 이 값이다.
- **최종치 추정** = 당월 *d*일차 누적 ÷ 과거 12개월 평균 "*d*일차 누적/최종치" 비율.
  누적이 쌓일수록 신뢰구간이 좁아지고, 화면에는 범위로 표시한다.

### 4.3 신고가 판정

- 비교 단위: **단지(단지일련번호) × 전용면적 그룹**(소수점 버림, 예: 84.91 → 84)
- `prev_high` = 이 거래 **이전 계약일**에 체결되고 해제되지 않은 거래 중 최고가
- 신고가 = `price > prev_high`
- 화면 표시값
  - 전고점 대비율 = `price / prev_high` (예: 19억 대비 96.84%)
  - 상승액 = `price - prev_high`
  - 상승률 = `price / prev_high - 1`
- **직거래**와 **이후 해제된 거래**는 기본적으로 전고점 산정에서 제외한다. 옵션으로 포함할 수 있다.
- "오늘 나온 신고가" = `first_seen_date = 오늘` 이면서 신고가인 거래

### 4.4 가격 모멘텀

- 주간·연간 변동률은 R-ONE 지수에서 계산한다.
- 연속 상승 주수 = 최신 주부터 거꾸로 세어 변동률이 0보다 큰 주의 연속 개수
  (서울 "88주 연속 상승")
- 지역 순위 = 주간 변동률 기준 정렬, 연간 변동률 병기

### 4.5 매크로 카드 공통 포맷

모든 지표를 같은 구조로 저장하고 같은 카드 컴포넌트로 그린다.

```
{ series_id, name, unit, value, as_of, change, change_basis('전월'|'전년동월'|'전일'),
  sub_values: [{label:'🇺🇸', value:4.00}, ...], next_release, history[] }
```

## 5. 인사이트 계층 (송희구 관점 체크리스트)

관점 근거는 [insights/viewpoints.md](insights/viewpoints.md) (작가 본인 채널 자막, 타임스탬프 링크).
출처 정책은 [INSIGHT_SOURCES.md](INSIGHT_SOURCES.md).

### 5.1 관점 수집으로 바뀐 설계

| 초기 가정 | 바뀐 설계 | 근거 |
|---|---|---|
| 지역 신호 점수 → 국면 **예측** | **과열·침체 관찰 체크리스트**. 판정은 사용자가 한다 | M1 "무조건적인 규칙은 적용되지 않는다", M2 |
| 시장 전체 거래량이 가격을 선행 | 전체 거래량은 신고 지연 보정 현황판으로만. **단지별 거래량(환금성)**이 핵심 | V1 "전체 거래량은 의미가 없다", V2 |
| 거래량↓ = 하락 신호 | 거래량↓ + 신고가 유지 = 매물 잠김(정상). 하락 초입은 **매매·전세 매물 동시 증가 + 호가 하향** | V2, C5 |
| 지역 단위 분석 중심 | **단지 × 평형** 단위가 중심. 지역은 급지 체인으로 연결 | P1~P3, L1 |
| 전세가율 중심 | 매매·전세 **실거래 가격 자체**의 4분면. 전세가율은 보조 | J1, J2 |

### 5.2 체크리스트 구성

홈 화면은 "압력 저울"(R4) 한 장과 체크리스트 네 묶음으로 구성한다.
항목마다 현재값, 기준선, 근거 관점 ID(링크)를 같이 보여준다.

| 묶음 | 항목 (관점 ID) | 데이터 |
|---|---|---|
| **과열 신호** | 하위 급지·구축의 신고가 비중↑ (C2) / 상승 지역 확산도 (C2) / 주간 상승 가속 (C4) / 전국 동반 상승 (C3) | 실거래, R-ONE |
| **하락 초입 신호** | 매매+전세 매물 동시 증가 (C5) / 실거래 대비 호가 하향 (P4, P5) / 대출 증가율 둔화 (R2) / 주담대 금리 5%·7% 돌파 (R3) / 실업률 상승 (R5) | 매물, ECOS, KOSIS |
| **상승 압력** | 전월세 실거래 급등·매물 부족 (J5) / 매매↓전세↑ 구간 (J2) / 공급(인허가·착공) 감소 (S1, S4) / 유동성 증가율↑ (R1) | 전월세 실거래, KOSIS, ECOS |
| **구조 변화** | 토허제 지정·해제 (G1) / 풍선효과 (G2) / 가격대별 분화 (L5) | 정책 이벤트 테이블 |

### 5.3 단지 분석 화면 (신규)

관점의 절반 이상이 단지 단위라서 **단지 상세 화면**을 별도 탭으로 추가한다.

- 기준 시세: 최근 60일 실거래(1층 제외), 거래 없는 평형은 같은 단지 평형 간 보간 (P1, P3)
- 호가 점검기: 호가 입력 → 기준 시세 대비 프리미엄 ≤3% / 3~5% / >5% (P2)
- 환금성: 세대수 대비 거래 회전율, 2022H2~2023초 하락기 거래 유지율 (V3, V4)
- 회복력: 2023-01 저점 대비 추세, 지난 하락기 낙폭·회복률 (C6, C7, D2)
- 매매·전세 실거래 나란히 + 4분면 위치 (J1, J2)
- 비교 단지 5개 자동 추천 (P3), 급지 체인상 상·하위 단지 (L1)
- 갈아타기: 목표 단지와의 **절대 금액 격차** 추이, 1.5배 후보 필터 (L3, L4)

### 5.4 규칙 파일 형식

```yaml
- id: C2_lower_tier_new_highs
  group: 과열 신호
  viewpoint: C2                               # viewpoints.md 카드 ID (필수)
  source: https://www.youtube.com/watch?v=HWJULtSpT7w&t=229
  metric: new_high_ratio_4w{tier=하위급지, age>=20y}
  thresholds: {watch: 0.15, alert: 0.30}      # 기준선은 백테스트로 조정
  message: "하위 급지 구축 거래의 {value:.0%}가 신고가입니다. 작가는 이를 상승장 끝자락 신호로 봅니다."
```

- `viewpoint`·`source`가 없는 규칙은 로드하지 않는다.
- 기준선(threshold)은 작가가 숫자를 말한 경우(3%·5%, 1.5배, 주담대 5%·7%, 전세가율 60%·50%·80%)만
  그대로 쓰고, 나머지는 과거 데이터(2021 고점, 2023 초 저점)로 백테스트해 정한다.

### 5.5 데이터 공백

| 공백 | 필요한 관점 | 대안 |
|---|---|---|
| **매물 수·호가** (공공 API 없음) | P2, P4, P5, C5 | ① 관심 단지 호가를 직접 입력 ② 공개 매물 사이트 수집 (이용약관 검토 후 결정) |
| 급지(tier) 정의 | C1, C2, L1 | 초기: 구 단위 평균 평당가 순위로 자동 분류 → 체인은 수동 보정 |
| 정책 이벤트 (토허제 등) | G1, G2 | 지정·해제일을 수동 관리하는 `policy_events` 테이블 |
| 실업률·고용 | R5 | ECOS/KOSIS 고용 지표 추가 |

## 9. 단계별 로드맵

| 단계 | 범위 | 완료 기준 |
|---|---|---|
| **1. 수집기 가동** | 서울 매매·전월세 실거래 일일 스냅샷 + 과거 이력 적재(2020~), DB 스키마, cron | 매일 `first_seen_date`가 쌓임 |
| **2. 오늘의 실거래 + 단지 분석** | 신고가 판정, 기준 시세, 환금성·회복력, 매매·전세 4분면, 호가 직접 입력 | "오늘 나온 신고가 N건", 단지 화면 |
| **3. 거래량** | 경과일 누적곡선, 동시점 대비, 일별 등록건수 | 화면 2~5번 재현 |
| **4. 가격 동향** | R-ONE 주간 지수, 구 단위 지도, 연속 상승, 순위 | 화면 1번 재현 |
| **5. 시장지표** | ECOS·FRED·KOSIS 카드 10종 | 화면 7~9번 재현 |
| **6. 체크리스트** | 규칙 파일 로더, 급지 분류·체인, 정책 이벤트, 기준선 백테스트 | 홈 화면 압력 저울·체크리스트 |
| **7. 입지 분석** | MapLibre 레이어(교통·개발·환경·인구) | 화면 10번 재현 |
| **8. 확장** | 수도권 전체, 전세가율, KB 시세, 알림 | |

1단계는 데이터가 쌓이는 데 시간이 걸린다. 그러므로 **가장 먼저, 다른 단계와 병행해서** 진행한다.
