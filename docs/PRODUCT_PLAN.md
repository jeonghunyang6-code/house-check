# 제품 계획: 사용자 상황, 합의 사항, 산출물 (2026-10-11 합의)

## 1. 사용자 상황 (모든 설계 판단의 기준)

- 2030 직장인, 부동산 공부를 막 시작한 **왕초보**. 개인용.
- **2027~28년 서울·경기 첫 매매** 계획. 투자 가치도 있는 매물을 원하고, 이후 **갈아타기로 상급지** 이동이 목표.
- 정책·규제·시장 심리에 시세가 민감하게 변하는 환경에서 **신중하게** 진행하고 싶다.
- 통용 규율은 **송희구 작가의 부동산 관점**(docs/insights/)이다.
- 원하는 분석: ① 전체 시세 트렌드 ② 입지(동네) ③ 아파트 간 투자 적합도 ④ 시장 상황 ⑤ 관심 아파트 상세(매매·호가) ⑥ 호재 ⑦ 정책·규제 반영 ⑧ 갈아타기.
- **시간이 자산**: 2027~28 매수이므로 지금은 데이터를 쌓는 시기. 등록일(`first_seen_date`)은 소급 불가 → 수집 가동이 최우선.
- 초보라서 모든 지표에 "무슨 뜻이고 왜 보는지" 한 줄 + 영상 시점·책 쪽수 출처를 붙인다 (학습 자료 겸용).

## 4. Supabase + GitHub Actions 설정 (사용자 작업, 완료·진행 상태)

1. Supabase 가입(GitHub 로그인) → New project `house-check`, Region **Northeast Asia (Seoul)**, Free. **완료**
2. Connect → **Session pooler** 접속 문자열 복사(Direct는 IPv6 전용이라 Actions 러너에서 안 될 수 있음, 확인 필요). `[YOUR-PASSWORD]` 대괄호까지 실제 비밀번호로 교체. **완료했으나 값이 잘림(아래)**
3. **비밀번호 특수문자는 퍼센트 인코딩**: `#`→`%23`, `@`→`%40`, `:`→`%3A`, `/`→`%2F`, `$`→`%24`, `%`→`%25`, `&`→`%26`, `?`→`%3F`, 공백→`%20`. 환경 설정의 `#`은 주석으로 읽혀 값이 잘린 것으로 추정. 사용자 PC(Windows cmd)에서 `python -c "import urllib.parse;print(urllib.parse.quote(input('pw: '),safe=''))"` 로 변환(`getpass` 버전은 입력이 안 보여 혼란을 줌). 결과를 채팅에 붙여넣지 않는다.
4. GitHub 저장소 Settings → Secrets and variables → Actions: `DATA_GO_KR_SERVICE_KEY`, `DATABASE_URL` 등록 (Actions용). **완료**
5. 클라우드 세션 환경: `DATABASE_URL` 환경변수 + 허용 도메인(`*.pooler.supabase.com` 계열) → **환경변수는 새 세션에서만 읽힘**
6. 제약: 스케줄(cron)은 **기본 브랜치에서만** 실행 → `main`으로 합쳐야 함(PR은 사용자가 요청할 때만 만든다). cron은 몇 분~수십 분 지연 가능. 비공개 저장소 Actions 무료 분량·Supabase 무료 용량/비활성 일시정지 한도는 기억 기준이라 **확인 필요**.

### 현재 상태 (2026-10-11)
- 클라우드 세션의 `DATABASE_URL`이 `postgresql://postgres.<프로젝트ID>:` 에서 끊겨 있었다(43자). 사용자가 비밀번호를 `%23` 인코딩해 다시 등록했으나 **그 세션은 변경 전 값을 계속 보고 있음** → 새 세션에서 확인.
- 새 세션 첫 작업: (a) `DATABASE_URL` 모양 확인(비밀번호 출력 금지: `@` 1개, `:5432`, DB명, `%23` 포함 여부) (b) `psql`로 접속 테스트, 실패 시 인코딩 vs 도메인 허용 구분 (c) 접속되면 `0001`·`0002` 적용(+ RLS 활성화 마이그레이션 추가)
- 이 환경은 PyPI 접속 불가 → psycopg 설치 불가. **DB 접근은 `psql` 명령**(Actions에서는 pip 가능하지만 같은 경로를 쓰기 위해 psql 유지).

## 5. 확인하지 못한 위험

- GitHub Actions(해외 러너)에서 국내 공공 API 접속 여부는 첫 실행으로 확인해야 한다 (이 클라우드 환경에서는 동작).
- 공공데이터포털 호출 한도가 수도권 전체 일일 수집에 충분한지 모름 (설계 문서는 운영계정 전제).
- K-apt 단지 정보·청약홈 API는 접속·승인 미확인. 청약홈은 `api.odcloud.kr`가 허용 도메인에 없어 막힘. K-apt 서비스명은 추측했다가 "서비스 없음"을 받음 → 포털 활용신청 페이지에서 확인.
- 후보 비교표의 🔧 기준선은 백테스트 전 초기 추정값.
- 서울 2020~ 이력 적재 후 용량을 재서 Supabase 무료 한도(약 500MB로 기억) 안에 들어가는지 결정.
